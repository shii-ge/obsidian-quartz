# Processos

> [!faq] Escreva um *shell* script que aceite dois números em ponto flutuante e exiba sua média aritmética.
> ```shell
> #!/bin/bash
> echo "Digite dois numeros para calcular a media:"
> echo -n "> Valor 1: "
> read x
> echo -n "> Valor 2: "
> read y
> echo ""
> echo "scale=2;($x+$y)/2" | bc
> ```

- **Problemas.**
	- Espera ocupada (*busy waiting*) - consumo ineficiente de CPU.
	- Confiar no processo (programador) - um processo dará a vez para algum outro.
	- Inversão de prioridades - ter CPU/prioridade e não querer entrar na região crítica.
- **Solução.**
	- Bloquear o processo ao invés de executar a espera ocupada.
	- Baseado em duas novas primitivas: `sleep` (bloqueia um processo e espera sinal) e `wakeup` (sinaliza um processo).
		- Um processo parado não consome CPU.
		- Comando `fg` (*foreground*) - atua como `wakeup`.

## Problema do produtor/consumidor
```
produtor() {
	while(TRUE) {
		produz_item();
		if (count==N) sleep();
		coloca_item();
		count = count + 1;
		if (count==1) wakeup(consumidor);
	}
}

consumidor() {
	while(TRUE) {
		if (count==0) <chaveamento> sleep();
		remove_item();
		count = count - 1;
		if (count==N-1) wakeup(produtor);
		consome_item();
	}
}
```

Nesse caso, as mudanças de contexto são imprevisíveis, já que podem ocorrer a qualquer momento.
- Após o `if(count==0)` do consumidor, ocorre um chaveamento antes da chamada de `sleep()`. Consequentemente, o processo consumidor vai para o estado de pronto em vez de ser pausado (`sleep`).
- Sinais de `wakeup()` são perdidos.
