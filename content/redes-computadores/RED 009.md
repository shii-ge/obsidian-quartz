# Protocolo HTTP e a Web

O **protocolo HTTP** (*Hypertext Transfer Protocol*) atua principalmente na camada de aplicação, e é responsável pela utilização da arquitetura cliente-servidor para aplicações.

O **World Wide Web (WWW)** é um sistema distribuído e colaborativo de informação de hipermídia, e constitui a aplicação que popularizou a internet.

Alguns protocolos utilizados na *web* são:
- HTML: *HyperText Markup Language*
- URL: *Uniform Resource Locator*
- HTTP: *Hypertext Transfer Protocol*

> **Tim Berners-Lee**, em 1989, propôs a implementação do protocolo HTTP em uma RFC da IETF. Atualmente, está na versão 3.

Outros usos do protocolo HTTP incluem: APIs HTTP, clientes de linha de comando (ex.: `curl`, `wget`), comunicação de microsserviços, aplicações IoT.

## Cliente *web*

O cliente *web* do HTTP pode negociar idioma, codificação, compactação, tipos de arquivos e o tipo de conexão (persistente ou não).

- Protocolo baseado em texto legível.
- Cabeçalhos com campos e valores.
- Linhas separadas por CR (*carriage return*) e LF (*line feed*).
---

O protocolo HTTP é um protocolo sem estado (*stateless*), cada requisição carrega as informações sobre ela.

**Cookies.** Enviadas ao cliente, reenviadas ao servidor em novos acessos, cabe a aplicação utilizá-las, garante segurança.

**Métodos:**
- GET
- HEAD - cabeçalho
- POST
- PUT
- POST
- DELETE
- OPTIONS

**Códigos de acesso:**

- 1xx - informação
	- 101 - troca de protocolo
- 2xx - sucesso
	- 200 - ok
	- 201 - criado (put)
	- 202 - aceito (post)
- 3xx - redirecionamento
	- 300 - múltiplas opções
	- 301 - movido permanentemente
- 4xx - erro cliente
	- 400 - bad request
	- 403 - forbidden
	- 404 - não encontrado
- 5xx - erro servidor
	- 500 - erro interno
	- 501 - função não implementada

**Proxy *web*.** Cache de dados -> redução de tráfego.
Filtragem - antivírus, controle de acesso, etc.
Balanceamento de carga, autenticação e autorização, registro de informação.

> **Nascimento do HTTP**

- **Motivação de Berners-Lee (1990).**
	- Transferência de arquivos
	- Busca em índices de documentos
	- Negociações entre clientes e servidores
	- Encaminhamento de referência para outro servidor
- Protótipo de Berners-Lee
	- Requisição: *string* terminada por CRLF
	- Resposta em ASCII
	- Resposta em HTML
	- Conexão era fechada após transferência

## HTTP 1.0

Requisição composta por múltiplas linhas
Resposta: 1 linha de status, cabeçalho com vários campos, não limitada a hipertexto
Conexão fechada após resposta
Negociação pelo tipo de mídia
Codificação
Mensagens com partes em múltiplos tipos
Autorização
Cache
Comportamento de *proxies*

## HTTP 1.1

Otimizações e melhorias
Transferência *chunked*
Conexões persistentes: múltiplas requisições e respostas por conexão
Autenticação
